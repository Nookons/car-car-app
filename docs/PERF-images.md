# Фото: замеры «до/после» и ресайз на CDN

Проблема: карточка и лента грузили **полноразмерные** фотографии площадки даже
для миниатюр 64×48 и лент шириной ~600 px. У объявления с 40 фото это
несколько мегабайт на одно открытие — больно на мобильном интернете.

CDN otomoto/OLX умеет отдавать варианты через `;s=ШxВ` в пути. Исходник
1000×750 — 135 КБ, `;s=160x120` — 6 КБ, `;s=800x600` — 88 КБ.

## Замер

Объявление `240629` (40 фото), один и тот же URL, `curl -w %{size_download}`,
сумма байт; кэш CDN прогрет одинаково.

| Что | Было | Стало |
|---|---|---|
| Галерея: 40 миниатюр | 4.35 MB | 223 KB |
| Главное фото + 2 предзагрузки | 402 KB | 263 KB |
| **Итого карточка** | **4.74 MB** | **486 KB** (−90%) |
| Фотолента карточки в списке, 6 фото | 896 KB | 394 KB (−56%) |

Лайтбокс по-прежнему открывает оригинал: зум не теряет качество.

## Что изменено

- [`lib/photos.ts`](../lib/photos.ts) — `photoSize(url, w, h)`: подставляет
  `;s=ШxВ` только для `*.olxcdn.com`, чужие CDN не трогает; заменяет уже
  имеющийся размер, а не дописывает второй.
- [`components/photo-gallery.tsx`](../components/photo-gallery.tsx) — герой
  и предзагрузка 800×600, миниатюры 160×120, лайтбокс — оригинал.
- [`components/listing-photos.tsx`](../components/listing-photos.tsx) — лента
  в списке 640×480.
- [`components/similar-listings.tsx`](../components/similar-listings.tsx) —
  карточки похожих 320×240.

## Как повторить

```bash
curl -s http://127.0.0.1:8080/api/listings/240629 > /tmp/card.json
# для каждого фото: curl -o /dev/null -w '%{size_download}\n' "<url>;s=160x120"
```

Проверено: `tsc --noEmit` без ошибок, `pytest` 80 тестов, размеры вариантов
подтверждены HTTP-запросами (200, `image/jpeg`, 160×120 / 800×600).
