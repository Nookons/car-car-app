# Как работает парсер

Один сборщик = одна площадка. Внутри — три независимых процесса (на Railway это
три сервиса): **инкрементальный опрос**, **обогащение карточек** и **полный
обход**. Все пишут в одну каноническую схему.

```
площадка (HTML)
   │  GET, 1 запрос/сек, brotli
   ▼
разбор __NEXT_DATA__ ──► Listing (канонические поля)
   │
   ├─ валидация: нет цены/битый id/URL → ingest_reject
   │
   ▼
upsert в listing  (unique source_id+external_id)
   │
   ├─ новая строка        → INSERT, попадает в очередь обогащения
   ├─ хэш изменился       → UPDATE + событие price_drop/price_up
   └─ ничего не изменилось → только last_seen_at
```

## Откуда данные

Страницы otomoto — Next.js. Вся выдача уже лежит в HTML внутри
`<script id="__NEXT_DATA__">`:

- выдача → `props.pageProps.urqlState` → `advertSearch.edges`;
- карточка → `props.pageProps.advert` (фото, кузов, цвет, продавец, VIN).

Поэтому браузер не нужен: обычный GET + `json.loads`. Одна страница выдачи —
32 объявления, ~1.7 МБ HTML, **177 КБ по проводу с brotli**.

## Три прохода

| Проход | Кто запускает | Частота | Что делает | Ограничения |
|---|---|---|---|---|
| **Инкремент** (`watch`) | сервис `CARCAR_MODE=watch` | каждые 60 с | первые 2 страницы выдачи, сортировка «свежие сверху» | 2 запроса/мин, 3 карточки за опрос |
| **Обогащение** (`enrich`) | сервис `CARCAR_MODE=enrich` | непрерывно | догружает фото/кузов/цвет/продавца для тех, у кого нет карточки | 1 запрос/с, свежие в приоритете |
| **Полный обход** (`sweep`) | сервис `CARCAR_MODE=sweep` | раз в сутки/по требованию | страницы 1…8051, весь рынок | 0.7 запроса/с, ~3 часа |
| **Очистка** (`purge`) | cron | раз в сутки | снятые старше 30 дней, логи старше 90 и т.д. | — |

### Инкремент: как ловит новое

1. `GET /osobowe?search[order]=created_at:desc&page=1` (и `page=2`).
2. Разбор → список `Listing` (id, цена, год, пробег, топливо, КПП, город, lat/lon).
3. Для каждой строки считается `content_hash` по каноническим полям.
4. Один запрос к базе: какие `external_id` уже есть.
5. Новые — `INSERT`; изменившиеся — `UPDATE` + событие; остальные — только `last_seen_at`.
6. Новые отправляются в обогащение: 3 карточки за опрос.
7. Стоп-правило: **2 страницы подряд, где >90% id уже известны** — дальше не листаем.

Почему не «остановиться на первом знакомом id»: площадка подмешивает
«поднятые» объявления со старой датой, сортировка нестрогая. Иначе пропустили бы
свежие, стоящие ниже старого продвинутого.

### Обогащение: почему отдельный процесс

Фото, кузов, цвет, продавец и VIN есть только в карточке. Карточек примерно
столько же, сколько новых объявлений (~5/мин), а живой опрос не должен ждать:
иначе новые объявления копятся без фото. Поэтому отдельный воркер берёт очередь
`details_fetched_at is null` (свежие первыми), качает по одной и записывает:

- фото — до 60 URL;
- кузов, цвет, мощность, объём;
- продавец (имя, тип), VIN (если площадка его отдала);
- точные координаты (`seller.location.map`) — они точнее города.

`404/410` → объявление помечается `removed` и уходит из очереди, а не качается
вечно.

### Полный обход: история и проверка снятых

Инкремент видит только новые объявления. Чтобы забрать рынок целиком, `sweep`
идёт по страницам 1…8051 (32 объявления на страницу). Прогресс хранится в
`sweep_state` — после рестарта контейнера продолжает с того же места. Повторный
проход безопасен: `upsert` по `(source_id, external_id)`.

## Что считается «новым» и почему нет дублей

- Уникальность `(source_id, external_id)` на уровне базы.
- `content_hash` — SHA-256 по title, price, mileage, year, make, model, fuel,
  gearbox, city, координатам. Если хэш не изменился — строка не перезаписывается.
- История цены пишется только при изменении (`listing_event`), а не на каждом
  опросе.
- Валидация до записи: нет цены, битый id, http-URL, пробег вне диапазона,
  мощность вне 10–2000 — запись уходит в `ingest_reject` с причиной.

## Вежливость к площадке

- 1 запрос/с по умолчанию (`--rps`), обход — 0.7.
- `429/503` → пауза 10–20 с перед повтором, `Retry-After` уважается.
- `403` → `BlockedError`, ретраев нет (это не таймаут, а запрет).
- Ошибки: экспоненциальный бэкофф 60 → 120 → … → 600 с.
- **Авто-пауза** после 5 ошибок подряд (watch) или 8 (sweep): коллектор сам
  останавливается, чтобы не долбить площадку, и пишет причину в `collector`.
- Пауза ставится и вручную — из дашборда или `carcar pause --source otomoto`.

## Что видно снаружи

Каждый опрос пишет `collector`: статус, время опроса, счётчики, ошибка.
Каждый прогон — `crawl_run`: страницы, вставлено, обновлено, отклонено, ошибки.
Дашборд читает это и показывает: статус коллектора, «объявлений в базе»,
прогресс обхода, графики по дням/месяцам и таблицу площадок.

## Ограничения

- **VIN** площадка отдаёт редко — пусто не из-за парсера.
- **Описания не храним** (1–3 КБ на объявление); в карточке есть ссылка на оригинал.
- **Фото — ссылки на CDN**, байты не качаем: и по правам, и по объёму.
- Новые площадки: свой модуль разбора → те же канонические поля → свой сервис
  с `CARCAR_SOURCE`; схема и дашборд уже мультиплатформенные.
