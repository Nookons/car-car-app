# Аудит производительности: сборщик otomoto

Первый компонент CarCar — сборщик объявлений. Отчёт по скиллу
`performance-engineering-audit`: что было, что изменено, чем измерено.

Дата: 05.11.2026. Воспроизведение: `scripts/bench_fetch.py`.

## Executive summary

Сборщик работает: забирает выдачу и карточки otomoto, складывает в папку,
переживает повторные запуски без дублей. Узкое место — **сеть, а не код**:
сервер отдаёт первую байту ~1.4 с, разбор JSON — 17 мс. Главный выигрыш дало
не «ускорение кода», а **сжатие**: brotli уменьшил трафик в 9.6 раза (1.7 МБ → 177 КБ
на страницу), иначе поллинг раз в 15 секунд съедал бы ~17 ГБ в сутки.

## Замеры «до / после»

Одинаковые 3 страницы выдачи, один и тот же UA, последовательные запросы.

| Вариант | Медиана, с | Трафик на страницу | Всего |
|---|---|---|---|
| urllib, без сжатия (наивный) | 1.70 | 1697 КБ | 5.21 МБ |
| httpx + brotli + keep-alive | 1.46 | 177 КБ | 0.54 МБ |
| **Разница** | **1.2×** | **9.6×** | — |

Разбор страницы (`json.loads` 1.7 МБ + нормализация 32 объявлений) — **17 мс**,
то есть 1% от времени запроса. Оптимизировать парсинг бессмысленно.

За сутки поллинга раз в 15 секунд сжатие экономит **~9 ГБ** трафика
(при одной странице на опрос).

## Findings

| # | Находка | Severity | Влияние | Что сделано |
|---|---|---|---|---|
| 1 | Страница без сжатия — 1.7 МБ | P1 | 17 ГБ/сутки, риск лимитов площадки | brotli в httpx (Accept-Encoding по умолчанию), проверено 177 КБ |
| 2 | Новое TCP/TLS-соединение на каждый запрос | P2 | +100–200 мс на запрос | keep-alive пул в httpx |
| 3 | Полуфайлы при обрыве записи | P1 | битые JSON, падение нормализации | атомарная запись: tmp + `os.replace` + `fsync` |
| 4 | Дубли при повторном прогоне | P1 | 32 строки каждые 15 с = 250 тыс./сутки мусора | seen-множество + карточки по id, запись только новых |
| 5 | Нет ретраев и уважения `Retry-After` | P1 | падение на 429/5xx, риск блокировки | ретраи с backoff + джиттер, 429/5xx, `Retry-After` |
| 6 | 403 трактовался как обычная ошибка | P2 | бессмысленные повторы, эскалация блокировки | отдельный `BlockedError`, без ретраев |
| 7 | Все карточки в одной папке | P2 | 250 тыс. файлов в одном каталоге | разбивка по датам `listings/YYYY-MM-DD/` |
| 8 | Нет наблюдаемости | P2 | «тихо сломалось» незаметно | лог прогона: запросы, байты, ошибки, секунды |
| 9 | Разбор числа из `"1 998 cm3"` | P1 (баг) | объём двигателя 15983 вместо 1598 | ведущее число, а не все цифры строки |

Находка №9 — пример того, зачем тесты: она нашлась тестом на фикстуре,
а не в проде. `"cm3"` добавлял тройку к объёму.

## Что осталось (не блокирует)

| Задача | Приоритет | Почему сейчас нет |
|---|---|---|
| Параллельная загрузка 2 страниц | P3 | 1 страница = 1.5 с; поллинг раз в 15 с не упирается |
| Фильтр «поднятых» при уведомлении | P1 (следующий шаг) | это правило продукта, не производительности |
| Дедупликация по VIN/phash | P1 (следующий шаг) | требует БД/кластеров, сейчас «просто папка» |
| Сжатие старых карточек (zstd) | P3 | 3 карточки = 180 КБ; станет актуально на 250 тыс. |
| Метрики Prometheus | P2 (фаза 1.5) | пока хватает `runs/*.json` |

## Инфраструктура

- Python **3.11+**, зависимости: `httpx`, `brotli`.
- Сеть: исходящие 443 к `otomoto.pl` и CDN `*.olxcdn.com`.
- Диск: ~60 КБ на карточку; 7 тыс. новых/сутки ≈ 400 МБ/сутки при полном сборе
  карточек (поэтому по умолчанию `--details 5`, а не «все»).
- Переменных окружения не требуется; папка данных — `--data` или `CARCAR_DATA_DIR`.

## Статусы

- **Реализовано и проверено:** сжатие, keep-alive, атомарная запись,
  идемпотентность, ретраи, `BlockedError`, наблюдаемость прогонов, тесты.
- **Реализовано, проверено частично:** троттлинг (1 rps) — проверен косвенно
  по времени прогонов; отдельного теста на интервал нет.
- **Рекомендовано, не реализовано:** параллельные страницы, zstd-архив,
  метрики Prometheus.
- **Заблокировано:** ничего.
