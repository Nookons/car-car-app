# Языки и локализация

Продукт для Польши, но пользователи — не только поляки: украинцы и белорусы
покупают машины в PL массово, плюс экспаты и партнёры-дилеры. Поэтому
мультиязычность — не «когда-нибудь», а часть MVP.

## Языки

| Язык | Код | Роль | Объём |
|---|---|---|---|
| Польский | `pl` | основной рынок, язык источника | 100% |
| Украинский | `uk` | крупная аудитория покупателей в PL | 100% UI |
| Русский | `ru` | владелец и русскоязычная аудитория | 100% UI |
| Английский | `en` | экспаты, партнёры, разработка | 100% UI |

Пятый язык (немецкий) — только если пойдём в DE. Архитектура к этому готова
сразу: добавление языка = новый каталог, без правок кода.

## Что переводим, а что нет

**Переводим полностью:** интерфейс Mini App, сообщения бота, push-уведомления,
ошибки и подсказки, FAQ и поддержку, письма (если появятся), страницы
политики и условий, статус-страницу, тексты кнопок.

**Не переводим:** описания объявлений и заголовки площадки. Причина не в
лень: машинный перевод описания автомобиля — прямой путь к обману покупателя.
«Bezwypadkowy» нельзя отдавать как «no accidents» (это заявление продавца,
а не факт), «stan bardzo dobry» и «igła» — оценочные суждения. Карточка
показывает оригинал и явно помечает язык: «Opis w oryginale (PL)».

Названия марок/моделей — латиницей как в источнике, без транслитерации:
«Mercedes-Benz Klasa C», а не «Мерседес-Бенц С-класс». Иначе поиск и
дедупликация развалятся.

## Каталоги и формат

Один формат для бота и приложения — ICU MessageFormat в JSON, с неймспейсами:

```
locales/
  pl/
    common.json      # кнопки, навигация, ошибки
    listing.json     # карточка, характеристики, цена
    sub.json         # подписки, фильтры
    notify.json      # тексты push
    errors.json      # коды ошибок → человеческий текст
  ru/  uk/  en/      # те же файлы, те же ключи
```

Ключ — смысловой, не по тексту: `notify.new_listing.title`, а не
`new_car_found`. Тексты меняются, ключи — нет.

Пример плюрализации (польский — 4 формы, не 2):

```json
{
  "notify.new_listing": {
    "title": "Nowe ogłoszenie",
    "body": "{count, plural, one{# nowe auto} few{# nowe auta} many{# nowych aut} other{# nowego auta}}"
  }
}
```

```json
{
  "notify.new_listing": {
    "title": "Нове оголошення",
    "body": "{count, plural, one{# нове авто} few{# нові авто} many{# нових авто} other{# нового авто}}"
  }
}
```

Русский и украинский — три формы (`one/few/many`), английский — две.
Поэтому «просто подставить число» нельзя: формы задаются в каталоге, а не в коде.

## Библиотеки

| Где | Что | Почему |
|---|---|---|
| Mini App (TS) | `@formatjs/intl-messageformat` | стандарт ICU, плюрализация и форматирование из коробки |
| Бот (Python) | `PyICU` (libicu в docker-образе) | те же ICU-сообщения — один набор каталогов на два рантайма |
| Проверка ключей | скрипт + тест паритета в CI | расхождение каталогов видно до релиза, а не в проде |

Если `PyICU` окажется тяжёлым для образа, альтернатива — `Babel` только для
множественных форм, но тогда каталоги придётся держать в двух форматах.
Это худший вариант: ровно тот класс дефекта, когда «одна строка живёт в двух
местах и расходится молча». Поэтому сначала PyICU.

## Форматирование

| Что | Правило | Пример |
|---|---|---|
| Цена | `Intl.NumberFormat(locale, {style:'currency', currency:'PLN', maximumFractionDigits:0})` | `45 000 zł` |
| Пробег | числа с разделителем разрядов + `km` | `222 693 km` |
| Дата | Europe/Warsaw, абсолютная в карточке, относительная в ленте | `2 min temu`, `05.11.2026` |
| Время | 24-часовой формат (PL/UA/RU), 12-часовой для `en` | `14:30` |
| Расстояние | км, не мили | `12 km` |

Валюта — из объявления; **не конвертируем** валюты и не показываем «примерно
в евро». Курс устаревает, а цена — главное число в карточке.

## Бот

- Язык по умолчанию — из `language_code` пользователя в Telegram.
- Явный выбор в `/settings` перекрывает автоматический и хранится в
  `app_user.lang`.
- Команды регистрируются с `language_code` через `setMyCommands` —
  у каждого языка свой список, в том числе описания команд.
- Текст пуша собирается **в момент отправки** на языке получателя; в очередь
  кладётся не готовая строка, а `(template, params, user_id)`.

## Контроль качества

- **Паритет ключей** — тест в CI: набор ключей в `pl` == в `ru`/`uk`/`en`,
  и набор в Python-каталоге == в TS-каталоге. Это тот же класс дефекта, что
  «одна функция в двух репозиториях»: два каталога расходятся молча.
- **Пропущенный ключ — не тихий фолбэк.** В проде отдаём `pl`, но пишем
  метрику `i18n_missing_key_total{key,locale}` и алертим, если растёт.
- **Псевдолокализация** `en-XA` (текст +30% длины) на staging — ловит
  обрезанные кнопки и вёрстку, которая держится только на коротких словах.
- **Ревью носителем** для `pl` и `uk` перед релизом. Машинный перевод
  в прод-интерфейс не пускаем: он даёт «польский» с русским порядком слов,
  и это видно с первой карточки.
- Переводы — часть релиза: версионируются в git, проходят ревью, попадают
  в changelog.

## Контент, который тоже локализуется

FAQ, шаблоны поддержки, тексты ошибок, страницы «Политика конфиденциальности»
и «Условия», уведомления о сбоях, статус-страница. Если этого нет на языке
пользователя — он не чувствует, что продукт «для него», даже при идеальном UI.

## Что это добавляет к плану

- Каталоги `locales/*` — часть фундамента, не «полировка в конце».
- В API и боте — только ключи, никаких строк в коде (кроме логов).
- Тест паритета и метрика пропущенных ключей — с первого дня.
- Оценка: **+1.5–2 дня** на каркас, дальше переводы идут вместе с фичами.
