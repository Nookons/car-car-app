# Архитектура: кеш, шина, уведомления

```
                    ┌──────────────┐
  otomoto ──► сборщик│  PostgreSQL  │◄── API (FastAPI) ◄── Mini App (Next)
                    └──────┬───────┘
                           │ listing.created
                    ┌──────▼───────┐      ┌──────────────┐
                    │ Redis Streams│─────►│   воркер     │──► Telegram Bot API
                    │ (или Kafka)  │      │ уведомлений  │
                    └──────────────┘      └──────┬───────┘
                           ▲                     │
                    Redis кеш ◄──────────────────┘
```

## Кеш

`carcar/cache.py` — Redis с деградацией в память процесса, если `REDIS_URL`
не задан.

| Что | TTL | Ключ |
|---|---|---|
| Выдача списка | 30 с | `list:<query>` |
| Карточка объявления | 10 мин | `card:<id>` |
| Справочники фильтров | 5 мин | `filters:*` |

Дашборд и скролл ленты больше не бьют Postgres на каждый запрос; при отказе
Redis сервис продолжает работать на локальном TTL-кеше.

## Шина событий

`carcar/bus.py`:

- **Redis Streams** (по умолчанию, `REDIS_URL`) — consumer group
  `carcar-notify`, at-least-once, `XACK` после обработки.
- **Kafka** (`KAFKA_BOOTSTRAP`) — тот же интерфейс, топик `listings`.
- **NullBus** — без окружения события уходят в лог.

Почему Streams по умолчанию: на сотни событий в день Kafka — это лишняя
инфраструктура. Адаптер готов: достаточно задать `KAFKA_BOOTSTRAP`, когда
понадобятся тысячи событий и несколько консьюмеров.

Событие:

```json
{"type": "listing.created", "source": "otomoto", "external_id": "6151002499"}
```

## Уведомления

`carcar/notify.py` + `carcar/worker.py`:

1. Сборщик после вставки новых объявлений публикует `listing.created`.
2. Воркер читает событие, находит объявление и активные подписки.
3. Матчинг по критериям: марка, модель, цена, год, пробег, топливо, КПП, кузов.
4. Пишет `notification` с уникальным `(user_id, listing_id)` — повторная
   отправка исключена на уровне БД.
5. Отправляет `sendPhoto` с подписью и кнопкой `web_app` на карточку.
6. Троттлинг: не более 25 сообщений/с глобально и 1 сообщение/с на чат.
7. Пользователи с `digest = true` остаются `pending` — их добирает дайджест.

Проверено на проде: событие → воркер → `notification.status = 'sent'`.

## Фото

- `SmartImage`: серый плейсхолдер → плавное появление по `onLoad`,
  `loading="lazy"` для карточек, `fetchPriority="high"` для первого экрана.
- Лайтбокс предзагружает соседние кадры (`new Image()`), листание мгновенное.
- Фиксированная рамка 68vh с `object-contain` — фото любого размера
  отображается одинаково.
- URL не проксируем: CDN отдаёт изображения с `cache-control`, экономия трафика.

## Параллельность

- API: пул соединений psycopg (до 6), параллельные запросы к Postgres.
- Фронт: `Promise.all` для независимых запросов (профиль + подписки + избранное).
- Сборщик: **намеренно последовательный** — параллельные запросы к otomoto
  ловятся WAF (проверено: 12 rps → 429 на всё). Темп: 0.25 запроса/с,
  джиттер, кулдаун 15–25 минут при 429.
